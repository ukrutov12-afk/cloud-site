# Zephyr Client — Render-ready сайт

Новая версия Zephyr с настоящей серверной авторизацией из старого Cloud-проекта. Схема таблиц и формат паролей сохранены, поэтому существующие пользователи продолжат работать при подключении той же `DATABASE_URL`.

## Возможности

- Express + EJS, готово для Render;
- регистрация и вход по email или username;
- bcrypt-хеши паролей и PostgreSQL-сессии;
- личный кабинет, аватар, смена пароля и сброс HWID;
- подписки, заказы и админ-панель;
- четыре языка: `be`, `ru`, `uk`, `en`;
- документы, тарифы, поддержка и плавный FAQ;
- локальный JSON-режим, если `DATABASE_URL` не задан.

## Локальный запуск

```bash
npm install
npm start
```

Открыть `http://localhost:3000`.

## Обновление существующего Render-сервиса

1. Замените файлы в подключённом репозитории содержимым этого архива.
2. Не создавайте новую базу и не меняйте `DATABASE_URL`: именно она содержит существующих пользователей.
3. В Render оставьте команды:
   - Build Command: `npm install`
   - Start Command: `npm start`
4. Проверьте переменные из `.env.example`. Обязательные для продакшена:
   - `NODE_ENV=production`
   - `SITE_URL=https://ваш-домен`
   - `DATABASE_URL=...`
   - `SESSION_SECRET=...`
   - `ADMIN_EMAILS=ваша-почта`
5. Запустите Manual Deploy → Deploy latest commit.

Секреты не должны попадать в репозиторий. Если `SESSION_SECRET` заменить, аккаунты сохранятся, но активные сессии завершатся.

## Покупки

По умолчанию `PURCHASES_FROZEN=true`: показывается предзаказ, а дни подписок считаются от `FROZEN_AT`. Для открытия демонстрационного потока заказов задайте `PURCHASES_FROZEN=false`. Реальный платёжный провайдер всё ещё нужно подключить в `POST /buy`.

Проверка состояния для Render: `GET /healthz`.
